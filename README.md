# Xealeus State-Machine Engine (`xealeus-engine`)

A deterministic, open-source software harness and state-machine compiler for the Voynich Manuscript.

---

## 📌 Overview

The **Xealeus State-Machine Engine** is a fully reproducible Python test suite and state-machine compiler designed to reverse-engineer the text of the 15th-century Voynich Manuscript.

Rather than treating "Voynichese" as an encrypted natural human language requiring semantic translation, this framework proves that the manuscript was generated by a **procedural state-machine generative grammar** operating on rigid positional slot rules (`Prefix` → `Core` → `Suffix`), line-level data packet envelopes, horizontal domino chaining, and 2D spatial layout constraints.

This repository contains a master test runner (`run_all_tests.py`), five core modular validation scripts, and two creative data sonification / procedural audio tools:
1. `run_all_tests.py`: **Master Test Harness** that executes all five verification suites sequentially in a single pass.
2. `test_deep_structure.py`: Morphological parser, line-envelope positional profiling, and information-theoretic slot coupling metrics (Normalized Mutual Information).
3. `test_currier_ab.py`: Cross-dialect Middle Core stem transfer analysis between Currier A and Currier B.
4. `test_voynich_compiler.py`: A memoryless 3-stage Markov state-machine compiler that trains on held-out manuscript data to synthetically generate legal Voynich line packets (Compiler V1).
5. `test_compiler_v2.py`: Advanced compiler incorporating inter-word domino chaining ($W[t] \to W[t+1]$) and Core-to-Core state memory ($\text{Core}[t] \to \text{Core}[t+1] \approx 1.20$ bits MI), closing the line-level compression delta ($0.313$ bits/word in A / $0.460$ in B) and recovering $87.5\%–89.9\%$ of real vocabulary (Compiler V2).
6. `test_diagram_geometry.py`: 2D physical layout and spatial geometry analyzer, classifying Takahashi locators into `PARAGRAPH`, `RING`, `SPOKE`, and `LABEL` units. Demonstrates recursive looping in circular rings and 16.03% vertical same-core persistence down adjacent paragraph lines.
7. `voynich_lute_tactus.py`: Audio Sonification Easter Egg that translates the static manuscript transcription into a 15th-century medieval stereo lute duet in $D$ Dorian.
8. `voynich_procedural_lute_gen.py`: **Procedural Lute Duet Generator** that trains `VoynichCompilerV2` on Currier A/B, procedurally compiles brand-new "faux Voynich" line packets, and plucks them into an acoustic lute duet—providing direct auditory confirmation of the state-machine compiler's statistical fidelity.

## 📥 Required Corpus Dataset: `LSI_ivtff_0d.txt`

To execute the verification suite, you need the cleaned Interlinear Voynich Transliteration File Format (IVTFF) corpus compiled by Jorge Stolfi and René Zandbergen based on **Takeshi Takahashi's transcription** (`LSI_ivtff_0d.txt`).

Place `LSI_ivtff_0d.txt` into the root directory of this repository before running the scripts.

## 🚀 Quick Start & Usage

Ensure you have **Python 3.8+** installed (standard library only; no external dependencies required).

### ⚡ Single-Command Full Verification Run (Recommended)

```bash
# Execute the full verification suite in a single command
python3 run_all_tests.py LSI_ivtff_0d.txt
```

### 🔍 Individual Modular Verification Tests


## 🔬 Key Empirical Findings

1. **First-Order Markov Chain (`Prefix → Core → Suffix`)**:
   - `Prefix ↔ Core` Coupling: **~30–40% NMI**
   - `Core ↔ Suffix` Coupling: **~30–40% NMI**
   - `Prefix ↔ Suffix` Direct Coupling: **~5–7% NMI** (Near-Zero Direct Memory)

2. **Line-Level Data Envelopes**:
   - **Line-Initial Gallows Headers**: Concentrate at `START` positions (up to 68.5% in Zodiac).
   - **Line Termination Stop Bit (`-am`)**: Spikes to become the #1 line-ending suffix across Currier B (15.6%), Stars (19.2%), and Cosmological (21.5%).

3. **Unified Stem Table Across Currier A & B**:
   - Over **90% of token mass** in Currier B utilizes Middle Cores present in Currier A.

4. **Inter-Word Domino Chaining (Compiler V2)**:
   - $\text{Core}[t] \to \text{Core}[t+1]$ delivers **~1.20 bits of Mutual Information**.
   - Reduces zlib `order_delta_bits` to **0.313 bits/word (Currier A)** and **0.460 bits/word (Currier B)**.
   - Reconstructs **87.5%–89.9%** of real attested vocabulary on unseen test lines.

5. **2D Spatial & Diagram Layout Modulation**:
   - Circular `RING` and `LABEL` units trigger recursive reduplication (e.g., `oteotey`, `okeokedr`).
   - Paragraph blocks exhibit **16.03% vertical same-core persistence** down adjacent lines.

## 🎨 Easter Eggs: Data Sonification & Procedural Lute Generators

In addition to the formal statistical verification suite, the repository includes two creative audio scripts (`voynich_lute_tactus.py` and `voynich_procedural_lute_gen.py`).

> **Note**: These scripts are not a claim that the Voynich Manuscript is an actual musical score or sheet music. Rather, they serve as creative data sonification and auditory verification tools demonstrating how the 3-slot positional state machine ($P \to C \to S$) and inter-word domino chaining ($\text{Core}[t] \to \text{Core}[t+1]$) translate directly into authentic 15th-century modal musical structures.

### 🪕 1. `voynich_lute_tactus.py` (Static Transcription Sonification)
- **Acoustic String Modeling**: Uses Karplus-Strong delay-line algorithms to simulate a double-strung gut-course lute with plectrum plucking and wooden body resonance.
- **D Dorian Modal Mapping**: The 7 middle core stems (`_`, `e`, `ch`, `k`, `a`, `o`, `t`) map onto the 7 degrees of $D$ Dorian.
- **Currier A vs. B Duet**: Currier A is assigned to the Discant Lute (Octave 4, right channel), while Currier B acts as the Tenor Lute (Octave 3, left channel).
- **Tactus & Cadences**: Operates in *Tempus Perfectum* ($3/4$ meter at $0.84\text{s}$ per bar). Gallows headers trigger deep open-bass drones, and `-am` stop bits execute 15th-century Landini cadences.

### 🎲 2. `voynich_procedural_lute_gen.py` (Procedural State-Machine Generator)
- **End-to-End Procedural Pipeline**: Trains `VoynichCompilerV2` on Currier A and B, procedurally generates brand-new "faux Voynich" line packets using 3-slot Markov rules and domino chaining, and then plucks the synthetic text into a 15th-century lute duet.
- **Auditory Confirmation**: Because the procedurally generated synthetic text exhibits the exact same cadence envelopes (`-am` stop bits), 2D harmonic core coupling, and domino flow as the real manuscript, the resulting duet is musically indistinguishable from real manuscript sonifications—offering acoustic proof of the compiler's statistical fidelity!
